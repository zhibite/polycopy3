## 2. 数据口径

- **经济盈亏（economic PnL）**：Polymarket PnL history 口径，约等于 `trade_pnl + fees + taker/maker rebate + yield`，并包含未实现盈亏的变化。它不是纯现金已实现盈亏。
- **成交额**：PnL history 的 `volume` 是**双边记账**（同一笔成交的买卖双方都计），约为 activity 单边现金流的两倍。本文正文用双边口径计算 PnL/成交额；成交结构部分用 activity 的 `usdc_size`（单边现金流）。
- **已平仓头寸按“平仓日”归属**：`positions_closed` 中 `last_event_at` 落在窗口内的头寸，其 `realized_pnl` 是该头寸**整个生命周期**的盈亏，不完全是窗口内新开仓的盈亏。因此“按入场价带”的统计是**窗口内平仓头寸的 cohort 统计**，用于观察盈利来源，不是严格的月度归因。
- **时间**：全部为 UTC；北京时间 = UTC+8。
- **快照**：数据抓取于 2026-11-23 02:44 UTC，之后的新成交、新持仓不在本文统计内。

## 5. 对跟单策略的含义

### 5.1 30–70c 跟单带

按当前配置（BUY 价格 0.30–0.70、目标金额 ≥$20、1% scale）：

| 指标 | 近 30 天 |
| --- | ---: |
| 符合规则的 BUY 信号 | **377 个（12.6 个/天）** |
| 目标名义金额 | $301.2K |
| 按 1% 计算我们的累计名义金额 | **$3.2K** |
| 我们的单笔中位金额 | **$2.93** |
| 带内平均 BUY 价格 | 0.4589 |
| 占全部 BUY 笔数 / 金额 | 9.1% / 9.6% |

带内平仓 cohort 的表现（见 3.4）：43 个头寸、成本 $567.2K、已实现 **+$353.5K**、ROI **62.3%**、胜率 **74.4%**，占窗口已实现 PnL 的 **56.5%**。

**结论：30–70c 筛选方向是对的**——用 17% 的 cohort 成本、9.6% 的 BUY 成交额，拿到了 56.5% 的已实现利润。被排除的两端：

- **0–30c**：228 个头寸、+$167.0K（26.7% 利润）、ROI 44.5%，但胜率仅 25.9%，属于高方差彩票仓；不跟是合理的风险取舍。
- **70–100c**：$2.39M 成本、+$104.6K（16.7% 利润）、ROI 4.4%；占用 72% 的 cohort 资金，收益很薄，不跟也合理。

**但要注意**：30–70c 带内 43 个头寸中，前 3 大（都是 ETH 跌破阈值 Yes）合计 $258.5K，占带内利润的 **73%**。这个“带内优势”高度依赖少数行情，样本只有一个月，不能当成稳定 edge。作为对照，全历史口径下 30–70c 头寸用约 **16%** 的入场成本贡献了约 **81%** 的 PnL，与本月的 56.5% 方向一致，但本月更依赖少数大赢家。

### 5.2 规模与验证效率

当前 `1% scale + $2 最小名义金额 + $100 最大名义金额` 的组合，导致：

- 30 天累计只有 **$3.2K** 跟单名义金额；
- 中位单笔 **$2.93**，377 个信号中有 157 个（42%）目标金额低于 $200，会被 $2 下限托底；
- 对 $10K 纸盘账户来说，这个规模产生的盈亏信号会被噪声淹没，一两个月内无法判断策略优劣。

如果目标是**验证策略**而不是模拟最终资金曲线，建议二选一：

1. 把 `min_notional_usd` 提高到 $10–20，或
2. 改用 `sizing_mode = "fixed"`、`fixed_notional_usd = 10–20`，同时保留 `max_market_usd = 500`。

这样单月累计名义金额会到约 $3K–$8K 量级（取决于 $10 还是 $20），样本仍然不大，但至少每笔的盈亏不会被 $2 的固定下限主导。**注意**：这会放大回撤，必须先确认纸盘能承受。

### 5.3 持仓期与资金占用

- 中位持有 **4.1 天**，p90 **26.6 天**；跟单资金会长期占用。
- 他大量通过 REDEEM/MERGE 退出，而不是 SELL；我们的纸盘虽然能用 Gamma 结算，但**目标持仓账本**必须同步处理这些事件，否则后续 SELL 的复制比例会漂移。
- 当前 `max_market_usd = 500` 是**按 condition** 限制的；f705 经常在同一 event 的多档阈值上同时持仓（例如 ETH $1,750 / $2,000 / $2,250 三档），这些头寸高度相关。建议增加**按 event 的总敞口上限**（`max_event_usd`），否则单一行情会同时打穿多个市场。

### 5.4 相关性与结算

- 48 个 event、432 个 condition；同一 event 下多档阈值同涨同跌，表面分散、实际集中。
- 26.4% 的 condition 同时买过 Yes 和 No；跟单时如果只镜像单边，可能复制到对冲腿的一部分，风险特征会变形。
- 链上信号源目前只订阅 `OrderFilled`，不处理 `PayoutRedemption` / `PositionsMerge` / `PositionSplit`；在切换到链上主链路前，必须补上这些事件或用 data-api `/positions` 定期对账（见 [docs/onchain_poc.md](onchain_poc.md) 第 4 节）。

## 6. 风险与限制

1. **单月异常，不可外推**：近 30 天 +$601K，前 30 天 +$72.7K；近 90 天 91% 的利润来自最近 30 天。11 月中旬的 ETH/BTC 下跌是主要催化剂，属于事件驱动收益。
2. **极度集中**：前 10 大头寸贡献 77.9% 的已实现 PnL；前 3 大贡献 41.4%。少数头寸的成败会完全改变月度结果。
3. **低胜率、右偏**：胜率 43.4%，249 个亏损头寸合计 -$369.9K；最大单笔亏损 -$44.9K。跟单必须能承受连续小亏。
4. **回撤不小**：窗口内最大回撤 -$88.0K；最差单日 -$31.5K。相对于 $601K 的月收益，回撤约 14.6%；但如果按跟单资金比例放大，体感会更明显。
5. **费用与返佣依赖**：手续费 $60.6K、净手续费 $41.4K；taker 返佣 $19.2K。返佣政策变化会直接影响收益。
6. **当前账本偏空尾部**：184 个未平仓头寸、$1.15M 成本，主要是高价 No；如果加密市场再次大幅下跌，这些头寸会同时受损。最大的 ETH $1,250 No 已经在浮亏。
7. **XRP 是负贡献**：37 个头寸亏 $34.5K，胜率 32.4%；不是所有标的都适合复制。
8. **快照限制**：数据截至 2026-11-23 02:44 UTC；之后 f705 可能已经调仓，当前持仓和盈亏会变化。
9. **cohort 归因误差**：按平仓日归属会把老仓位的终身盈亏算进本月，尤其是 30–70c 的 43 个头寸里包含窗口前建立的仓位；不要把它当成“本月新开仓的精确收益率”。
